# AutoPM 协作规则

- Codex 是本项目协调负责人，维护任务范围、优先级、依赖、执行者、审核与集成。其他 AI 每次只接一个明确任务包。
- 用户最新决定优先于历史规划。先读根 README 的当前决定，再读指定 Issue 和引用资料；发现冲突时记录并交协调方裁决。
- 派工必须具备：任务 ID、业务目标、允许修改路径/平台对象、输入、交付物、验收条件、依赖、执行身份。缺少真实执行者时保持未分派。
- 一个工作包使用独立分支或隔离输出目录；不得覆盖其他 AI 或用户的未提交修改。
- 执行 AI 提交产物、版本、测试实际结果、证据路径和未完成项。协调方读回结果并运行适用检查，不能仅凭“完成”自述验收或关闭。
- GitHub Issues 是开发管理记录；Airtable Tasks 是业务项目计划；业务 Issues / Issue Actions 是异常及措施。不得互相自动转为同一对象。
- 本地完成、已提交、远端同步、草稿、已发布、已验收分别记录。当前迁移包没有启动持续后台监控。
- 常用工具与配置由协调方在已有授权范围内维护。优先复用插件/API、现有 CLI；不把安装成功当作认证成功，不把 SSH 成功当作仓库写入成功。
- 令牌不进入任务正文、Git、日志或交付包。身份验证失败时保留可接续工作；不从无关应用提取凭据。
- 新生产发布、真实邮件发送和更大范围的数据写入按用户具体授权执行；历史任务卡不能扩大授权。
