# AutoPM 使用分工指南

所有成员先读 [根规则](../AGENTS.md)。用户确认业务与执行范围；Codex负责主维护和验收。

| 角色 | 责任 | 入口与交付 |
|---|---|---|
| Codex | 资料、规则、任务定义、分派、验收和获准集成 | [入口](team/codex/README.md) |
| DuMate | 指定的业务规则核查、资料任务；能力按任务验收 | [入口](team/dumate/README.md)；GOV-01本地outbox由Codex同步 |
| Qoder | 远程读取GitHub，在独立分支提交指定成果 | [入口](team/qoder/README.md)；PR交付 |
| ai-03 / ai-04 | 用户报告已配置，具体产品/身份和接入仍待独立验收 | [ai-03](team/ai-03/README.md) / [ai-04](team/ai-04/README.md) |

## 日常操作

1. 读取 [总协调Issue #1](https://github.com/sunny-06064710-3/autopm-dadhboard/issues/1) 指定的分支与自己任务的最新评论。
2. 将待办梳理成目标、步骤、修改范围、验收方法与依赖，提交给用户确认。
3. 确认后在原Issue留下范围、时间、执行身份、起始版本，再开始工作。
4. 将日志与变更写入 `collaboration/team/<角色>/outbox/<任务ID>/result.md`，采用 [DELIVERY](planning/templates/DELIVERY.md)。引用确认记录、测试结果和PR。
5. Codex直接读取并按 [REVIEW](planning/templates/REVIEW.md) 验收，用户不搬运整份成果。

每日检查只读取和生成待确认清单；定时能力由对应AI提供设置/运行证据，不凭提示词声称已启动。Skill只保存入口，完整规则以仓库为准。
