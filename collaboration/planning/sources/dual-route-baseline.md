# AutoPM 双路线功能与开发任务基线

日期：2026-09-10  
状态：讨论与任务梳理基线，尚未分派、尚未锁定工期。

## 最新方向

用户决定采用 Airtable 与 Power Apps 两条路线开发。当前重点是先梳理需要做的事情，随后由用户提出任务布置要求。

- 先定义共同业务功能、规则和验收标准，再分别拆分 Airtable 与 Power Apps 的实现任务。
- 两条开发路线不自动意味着双向数据同步或同一业务数据双重维护；两端数据职责、试用范围和长期选择尚待明确。
- Power Apps 路线此前选定 Dataverse 为目标数据平台；用户确认相关审批与访问权限尚未取得。
- 此次保存不授权开发、导入、部署、停用 Airtable、分派任务或创建新任务。
- 先前“停止继续建设 Airtable、整体迁往微软”的单路线假设已被本次双路线决定替代。
- 先前完整迁移方案保留为设计参考，不直接作为两条路线的已批准执行清单；优先级、范围及工期待任务拆分时确认。

## 产品目标

AutoPM 在统一入口中连接项目建立、计划执行、SKU 差异、问题恢复、周报维护和历史复用。用户维护一次业务事实，系统关联数据、执行规则并保留历史。团队能够独立操作，日常运行不依赖 AI 开发助手代办。

业务基线：Program 为产品族，Project 为一次开案；Project 与 SKU 多对多；每个 Project 对应一个 Factory；SKU 在项目中的执行状态与日期归属于 Project–SKU 关系。Project 保存主计划，SKU 仅保存必要的日期例外。

## 共同开发任务清单

以下顺序用于说明依赖，不等于已经批准的串行排期。

| 编号 | 开发任务 | 具体工作 | 预期结果 |
| --- | --- | --- | --- |
| T01 | 现有功能盘点 | 整理页面、模板、自动化、导入导出；标记保留、改善、合并及实际证据 | 明确已有能力和待办，避免遗漏与重复开发 |
| T02 | 数据与关系设计 | 明确 Program、Project、SKU、Task、Issue、People、Factory 的关系、身份和字段维护位置 | 关联与汇总正确，同一事实只维护一次 |
| T03 | Program 与项目浏览 | 列表、搜索、分类、状态筛选及 Program 下钻 | 快速找到项目与相关 SKU |
| T04 | Project Detail | 状态、阶段、关键日期、负责人、SKU 差异、问题及下一步 | 在一个页面判断和更新项目 |
| T05 | 新建项目与计划模板 | 查重、选择项目类型、关联 SKU、调用模板、预览任务与日期 | 新建项目后获得可执行计划 |
| T06 | 任务与计划维护 | 责任、日期、依赖、完成结果；区分 Baseline、Forecast、Actual | 团队维护真实进展并识别偏差 |
| T07 | SKU 差异管理 | 项目计划继承、项目内状态、日期例外及范围历史 | 同一 SKU 在不同项目中的执行互不覆盖 |
| T08 | 问题与恢复行动 | 问题事实、影响、根因、行动、责任、结果、验证关闭和重开 | 从发现到解决形成闭环 |
| T09 | 个人工作台与提醒 | 本人任务、行动、逾期、阻塞、待确认；提醒合并与升级 | 用户知道下一步，减少人工追问 |
| T10 | 批量导入与数据维护 | 上传、解析、预览、匹配、确认、错误修正与安全重试 | 团队可自行处理批量数据 |
| T11 | 周报与 Tracker 输出 | 从事实生成周报、保留来源与版本、兼容已有 Tracker 输出 | 减少重复录入并可追溯 |
| T12 | 模板、经验与 AI 辅助 | 模板版本、已验证案例检索、信息提取与摘要 | 复用经验，减少重复设计与整理 |
| T13 | 权限与系统管理 | 角色、规则、配置、操作历史、失败记录与维护责任 | 规则不靠人记忆，团队可持续维护 |
| T14 | 验收与发布 | 逐项功能验证、真实用户操作、数据核对与恢复方案 | 两条路线各自有可检查的交付结果；是否切换另行决定 |

## 后续任务拆分格式

每个任务保留一个共同业务编号，再按需要拆成 Airtable 与 Power Apps 子任务。不是所有任务都必须重复开发。

| 字段 | 要说明的内容 |
| --- | --- |
| 业务目的 | 谁遇到什么问题，完成后有什么改善 |
| 功能范围 | 用户操作、输入、自动处理、输出及明确不包含的内容 |
| 当前成果 | 已有实现、来源及验证证据；区分已构建与已验证 |
| 共用工作 | 规则、数据字典、样例、模板、测试等可共用资产 |
| Airtable 路线 | 实际需要新增、改善或验证的配置与代码 |
| Power Apps 路线 | 实际需要新增、改善或验证的配置与代码 |
| 前置条件 | 数据、其他任务、平台权限、许可和业务口径 |
| 验收标准 | 同一业务输入应得到的可检查结果 |
| 分派信息 | 负责人、优先级、依赖、预计工作量；布置任务时再确认 |
