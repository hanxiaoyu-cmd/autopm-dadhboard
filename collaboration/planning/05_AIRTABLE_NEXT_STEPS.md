# Airtable AutoPM：接下来需要完善什么

版本：v1.0｜2026-09-11｜业务视角的执行顺序梳理

本次基于9月10–11日两轮审计、现有开发蓝图和任务台账整理，未刷新线上状态。以下是尚未取得修复验收证据的事项；执行者接手时核对对应对象是否已变化，不重复开展全系统审计。

## 1. 当前要达成的结果

AutoPM已有Program、Project、SKU、任务、问题、自动化和Interface主体。下一步让这些能力连成可信、顺畅、团队可独立操作的工作流程：

**看清项目 → 找到本人工作 → 更新计划和结果 → 处理问题并验证 → 形成周报和可复用经验。**

网页执行者优先考虑DuMate。这是依据用户本次反馈的浏览器操控能力作出的安排偏好；本会话未独立验证新的浏览器执行结果，也未实际派发任务。之前的自动调度验证边界不用于否定此次用户反馈，但单次浏览器成功也不意味着所有复杂开发已验证。

## 3. 怎样排先后

### 第一批：让数据和工作队列可信

**AT-00的受影响对象基线 → AT-01统计 → AT-02个人工作 → AT-03关系。**

执行前的基线只覆盖本批要改的字段、自动化和消费者：记录原值、关联明细、测试环境和恢复办法。已有审计作为输入；无需让DuMate再产出一份18表全量审计才能开始本批工作。

统一完成规则、角色和关系默认契约由现有GOV-01/02承接。分成可验收子项并逐步解锁，不能为了先改一个总数字要求先完成所有历史身份清洗。

### 第二批：完成业务操作与项目详情

**AT-04建案/日期、AT-05问题闭环、AT-06导入可靠性 → AT-07团队入口、AT-08统一Project Hub → AT-09输出/提醒、AT-10案例/运维。**

DuMate可以在开发副本中先做Project Hub的界面布局、现有字段分组和绑定核对；涉及新状态、核验或新数据关系的正式业务操作，按前置任务通过后接入。不用不存在的数据生成看似完整的页面。

### 第三批：团队验收，再做增强

AT-11完成真实角色、完整链路、约20项目试用与两个连续周度周期。其后再安排AT-12高级计划交互、AT-13管理Review/轻量决策、AT-14有来源AI摘要和推荐。

Copilot和自主Agent保留未来范围。若发现某项被列为增强的能力实际是现有日常依赖，则按对等迁移原则重新纳入本轮，不静默删除。

## 4. 建议首先交给DuMate的三个小批次

| 次序 | 可独立交付的结果 | 执行边界与验收 |
|---|---|---|
| **A：修正任务总数显示**，AT-01子项 | 每个项目的Total反映实际关联任务数量，所有引用该字段的展示一致 | 先核对消费者，在获准测试环境修复既有Rollup；固定样例7/6/6/0及增减关联可对账。只完成此项不能宣称整个完成率已修好 |
| **B：整理My Work的逾期/本周队列**，AT-02子项 | 用户能看到真正逾期、当前周内和待处理的事项 | 使用Target及已定义时区/周窗口；Owner与参与者说明清晰，无日期进入例外；不发实际催办、不擅自扩展协作者 |
| **C：对齐两个Project详情入口**，AT-08设计子项 | 同一项目从不同入口进入，关键身份、任务、SKU和问题背景一致，显示英文且可读 | 先调整现有字段的布局/绑定/标签；按Issue整条显示原因、行动、Owner和日期；新业务操作等前置规则通过后接入，设计子项不代替AT-08完整验收 |

这三个批次分别改善“数字正确”“知道做什么”“看清项目”，结果可直接看到，也能客观核对。更复杂的22批量、模板排期和Bridge任务按对应工作包另行拆解。

## 5. 后续分工

- **本会话／协调方**：维护目标、字段语义、关系、规则与优先级；形成有边界任务书；审核执行AI交回的结果并更新状态。
- **DuMate优先**：通过浏览器执行Airtable表配置、Formula/Rollup、View/Interface、自动化触发/参数配置及实际用户流程测试。涉及复杂脚本时先有可审查版本和测试，再进行安装和平台验证。
- **程序／集成执行AI**：复杂排期、批量关联、解析、导入写入、重试和Tracker输出等程序工作。人员/AI尚未分派；可以根据实际能力安排DuMate承接其中独立部分。
- **业务／平台负责人**：真实角色和责任承接、环境连接、正式发布及运行结果验收。

DuMate的具体配置、代码和页面成果仍按提交/审核模板验收。用户反馈可操控浏览器是采用它的依据；不据此把未做的权限、发送、并发、长期运行测试标通过。

## 6. 当前执行状态

本次只梳理优先级并记录执行偏好，没有修改Airtable或启动DuMate。原AT-00～14任务编号、依赖与验收状态保持；本页的小批次是原任务的子项，不建立第二套互相竞争的任务台账。
