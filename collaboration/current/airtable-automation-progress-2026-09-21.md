# AutoPM Airtable 自动化阶段进展（2026-09-21）

本文记录 2026-09-18 至 2026-09-21 的实际工作成果、验证边界和下一步。仓库为公开仓库，因此省略 Airtable 对象 ID、内部记录、人员、邮箱、私有链接和原始运行附件。

## 当前主流程

```text
Project List
  -> Project Detail
     -> 生成任务（Basic + Change）
     -> 上传项目计划
     -> Task Owner / Date / Completion
     -> Task <-> Issue
     -> Project Progress / Project Report
     -> Daily Reminder
```

原则保持不变：业务规则放配置中；自动化执行规则；人工 Owner、日期和已确认业务数据不被重跑覆盖；缺少负责人时继续创建任务并给出警告。

## 本阶段成果

### 1. 任务生成和配置

- 已把 Basic 与 Change 收敛到一个用户操作：用户发起一次生成请求，系统先包含基础任务，再按所选变更补充任务。
- 旧的基础任务单独入口已关闭，当前合并入口已部署。
- 任务规则成为任务生成的配置来源；规则维护不需要修改生成脚本。
- 已验证规则覆盖、重复防护、必选任务、缺失配置检查和顺序重跑。
- 规则中的 Milestone 写入任务 Milestone，规则中的 Phase 写入任务 Phase；任务现有字段未改名。
- 生成任务按项目团队成员及其 Department 匹配负责人；没有匹配人时保留任务并显示警告。

### 2. 项目计划文件导入

- 保留一个正式上传入口；旧排期入口继续关闭。
- 当前支持 CSV 和 Microsoft Project XML；日期兼容常见斜杠日期和英文月份日期。
- 导入只识别平铺任务，跳过汇总行，不重建主任务、子任务、依赖或排期层级。
- 默认负责人使用项目 NPI；识别为完成的任务同时记录 NPI 完成确认。
- 已移除对已删除进度和父子任务字段的依赖；删除字段后的实际重跑成功，重复导入没有新增重复任务。

### 3. 任务编号和字段精简

- 任务编号恢复为 `Project ID + T + 顺序号`，生成、导入和手工任务使用同一显示规则。
- 已纠正已确认的测试任务错误编号；没有改动正确编号、任务内容或项目关联。
- 生成和导入脚本已移除对一批无用字段的依赖，因此这些字段删除后不会再造成运行失败。
- 继续保留稳定任务键，用于重复识别；同一项目并发创建仍没有数据库级唯一约束，必须避免同时运行多个创建入口。

### 4. 项目成员和负责人

- Project People 成为用户选择项目团队的主要入口。
- 任务负责人通过 `Project People -> People Department -> Task Department` 匹配，减少每个部门单独维护一套前台字段。
- Department 词汇已核对；无法匹配的部门不阻止任务创建，而是留给状态警告和人工补齐。
- 项目成员同步已有连续成功运行记录；当前仍有一份未发布草稿，需要在后续发布时确认不会覆盖用户手工选择。

### 5. Task 与 Issue

- 前台已整理为两条清晰入口：从任务创建/关联 Issue，以及从 Issue 选择同项目任务。
- 测试项目已验证项目、任务和 Issue 的关联显示。
- Issue 选择范围应受当前项目限制，用户不需要从全库 Issue 或 Task 中寻找。
- 旧的 Issue 协作人自动化仍有过期字段依赖，未被这次前台修复掩盖，后续需要单独修复或退休。

### 6. 日期、完成和项目进度

- 开始日期初始化继续只补空值：`Start Date = Due Date - 7 天`；不修改 Due Date，也不覆盖人工 Start Date。
- 项目进度汇总已部署，近期运行成功。
- 当前仍存在一个规则差异：任务公式按确认人数判断，项目汇总和提醒按当前 Owner 身份判断。应统一为“所有当前负责人确认完成”。
- 任务移出项目或删除后，旧项目是否立即重算仍需补验收。

### 7. 每日提醒

- 个人每日邮件提醒已部署，并在 2026-09-21 的计划运行中成功完成自动化执行。
- 前台已有提醒邮箱、订阅开关和默认发送时间说明。
- 仍需完成：全英文内容、发送时读取最新数据、邮件版式、非管理员新用户开通、进一步简化操作。
- 自动化执行成功不等于收件箱送达和内容完全正确；真实邮箱显示仍需人工验收。

### 8. Project Report 和界面

- 已完成项目报告详情布局：项目状态、进度、关键日期、最新更新和未关闭 Issue。
- 已准备 `Project List -> Project Detail -> Open Project Report` 的同项目跳转。
- 独立 Project Reports 导航入口已在草稿中隐藏，报告详情保留为内部页面，不删除数据。
- 该整合目前是未发布草稿；发布前需要在普通用户身份下再走一次完整路径。
