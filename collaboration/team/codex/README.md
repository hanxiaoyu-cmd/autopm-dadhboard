# codex 固定入口

协调负责人：维护任务与优先级、正式派工、检查证据、验收、整合及获准的 GitHub 发布。

1. 先读 [统一规则](../../AGENTS.md)、[当前决定](../../README.md)及[使用分工指南](../../使用分工指南.md)，再读自己的 inbox 正式任务。
2. 一次只接一个具备任务 ID、目标、允许路径、输入、交付物和验收条件的任务。没有正式任务保持待命；占位身份先由 Codex 明确后才接业务任务。
3. Codex 维护各成员 inbox 和获准的项目管理文件，读取各 outbox 并验收；修改业务实现仍遵循具体任务范围和隔离要求。生产修改、推送、合并、部署和通知须符合用户的具体授权；认证材料不得进入交接目录。
4. 采用 [DELIVERY 模板](../../planning/templates/DELIVERY.md)。提交至少包含 task_id、attempt、执行者、开始结束时间、实际状态、产物路径/哈希、检查结果及错误或未完成项；验收结论交 Codex 按 [REVIEW 模板](../../planning/templates/REVIEW.md)填写。
5. 先在 outbox/<任务ID>/ 保存回执或结果，再由 Codex 读回核验；已提交但尚未验收时不重复执行。重试沿用原 task_id、增加 attempt，并先说明原因。
6. 当前没有已验证的自动唤醒连接。本地任务文件存在不表示本 AI 已收到、开始或完成；本入口读写、GitHub 权限和无人值守能力均需分别实测。不得自行设置轮询、调度或提取其他应用认证材料。

inbox：正式输入；work：隔离工作；outbox：交付与回执。
