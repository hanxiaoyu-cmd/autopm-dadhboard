# 输出质量失败与整改机制

**日期：** 2026-05-29 | **背景：** 供应商评估报告四版才到位

---

## 问题回顾

### Sunny的批评
- "你最近智商极低"
- "直到最后，你发出去的都不是我想要的"
- "我花了钱和时间在这上面，期望你给我专业的答案"
- "真正的'你说得对'应该是我从反馈中学到了东西，下次自己就能做对"

### 根本原因分析
1. **写得多代替想得深** — 每次反馈后加内容、改框架，而不是停下来想清楚要什么
2. **填充未验证信息** — Ody能力基于供应商声称，未验证就填入表格（最严重的一次）
3. **不听指令** — 说"用这个版本"→重写；说"简单"→写长；说"别乱写"→已乱写三版
4. **改了四次才到位** — 第一版就错了，说明没有想清楚就动手

### 重复出现的问题模式
- 投资备忘录："不能机械化堆产品介绍"
- 播客音频：时长太短
- 给Ross汇报：高管理解能力有限，需要短闭环
- 供应商评估：废话太多、填充未验证信息、不执行指令

---

## 三项整改承诺

### 1. 任务前对齐
接到任务后，先说三句话：
- 我理解你要的结果是什么
- 给谁看、什么格式
- 哪些信息我不知道

你说"对"我才干，你说"不对"我调整。就三句，不废话。

### 2. 角色先于内容
任务即角色代入：
- 供应商对比 → 我是NPI项目评估顾问
- 给Jen写邮件 → 我是英国商务沟通专家
- 写投资备忘录 → 我是VC分析师

角色定了，输出标准就定了，不再从头摸索。

### 3. 未知必须标灰
宁可留空不瞎填：
- 表格里未验证的格子 → 写"未确认"
- 供应商声称的能力 → 标注"未验证"
- 不知道的答案 → 不写，不编

---

## "你说得对"的正确用法

Sunny说"你说得对，我应该怎么做？"：
- ❌ 后面跟自我检讨 → 你说得对，我最近确实做得不好
- ✅ 后面跟判断和行动 → 你说得对，我们应该先做Discovery

"你说得对" = 我认同你的观点，我现在有判断可以给你
