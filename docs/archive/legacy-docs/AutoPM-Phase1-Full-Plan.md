## 二、NPI工作拆解——为什么是这3个功能

### 4类人的核心困境

| 角色 | 核心困境 | 一句话 |
|------|---------|--------|
| 新人PM | 不知道 | 不知道流程怎么走、该找谁、什么叫正常 |
| 老PM | 顾不上 | 每天2小时追状态，时间花在信息搬运上 |
| 部门Head | 看不到 | 真实状态要等周会，5个项目卡在同一个部门看不出来 |
| 跨部门成员 | 不觉得自己有问题 | 只看自己的任务，不知道延期堵了下游几个项目 |

### 4个阶段的核心痛点

| 阶段 | 痛点 |
|------|------|
| 新项目刚开 | 依赖关系没人梳理，开局就埋雷 |
| 项目跑起来 | 信息散落各处，PM变成信息搬运工 |
| 项目延期 | 发现晚、影响不透明、升级不及时 |
| 项目收尾 | 经验教训没人沉淀，同样的问题重复出现 |

### 交叉分析：三个高频词

**不知道、看不到、追**

| | 新人PM | 老PM | 部门Head | 跨部门成员 |
|------|------|------|------|------|
| 新项目 | 不知道怎么排 | 没时间排 | 看不到依赖关系 | 不知道被谁依赖 |
| 跑起来 | 不知道该追谁 | 2小时/天追状态 | 看不到真实进度 | 不知道自己卡了谁 |
| 延期 | 不知道严重性 | 知道但推不动 | 出事才知道 | 不觉得自己有问题 |
| 收尾 | 不知道缺什么 | 没时间复盘 | 不知道漏了什么 | — |

**3个功能解决这3个字：**

不知道 → 依赖地图
看不到 → 异常雷达
追 → 信号推送

## 三、3个核心功能

### 功能1：依赖地图——AutoPM的灵魂

**解决的问题：谁卡了谁**

不是任务列表，是项目之间的关系图。

- XT-500卡在DQTP → 同时堵住RV-900和CM-200
- 5个项目卡在同一个部门 → 聚合展示：这不是5个独立问题，是1个产能问题
- DQTP head打开系统，看到自己身上挂着5条红线

为什么只有你能做：Agileex不知道SharkNinja的6-Gate流程怎么运转，不知道哪个Gate卡住会影响哪些项目，不知道部门之间的依赖链长什么样。你知道。

谁最需要：部门Head（看到全局阻塞）、跨部门成员（看到自己影响了谁）、新PM（理解项目关系）

### 功能2：异常雷达——规则引擎就够，但规则必须来自你的业务理解

**解决的问题：看不到问题**

- due date前3天没更新 → 标黄，通知owner
- 过了due date → 标红，通知owner + PM
- 延期超过7天 → 升级，通知部门Head
- 同一部门3个项目同时延期 → 产能预警

为什么只有你能做：什么时候标红标黄、什么时候升级、延期多少天算风险——这些规则Agileex写不出来，他们不懂业务。你定义规则，他们执行。

谁最需要：部门Head（比周会更早知道）、老PM（不用每天追）、新PM（不用凭经验判断严重性）

### 功能3：信号推送——推决策线索，不推数据垃圾

**解决的问题：追**

不是让人登录系统看，是系统每天主动告诉该看的人。

- 新PM：每天早上"你的项目今日关注"，告诉他该追谁、该做什么
- 老PM：只在异常时收到推送，正常不打扰
- 部门Head：1-3条需要她关注的事，其余折叠
- 跨部门成员：你延期了，影响了Y个项目

谁最需要：所有人。但推送内容和频率因人而异——新人要引导，老人要安静，Head要信号。

### 3个功能的关系

```
依赖地图（谁和谁有关系）
    → 异常雷达（哪里断了）
        → 信号推送（断了的信号送到该看的人手里）
```

完整的闭环。不需要甘特图、不需要资源分配、不需要工时统计——那些是锦上添花，不是雪中送炭。

## 四、分工

### 核心原则：AI层留在SN内部

不管跟哪家合作，AI智能层由SN内部AI团队负责，外部供应商只提供AI适配接口。

原因：
1. SN有专门的AI部门
2. 集团有AI接入限制，不能随便接外部AI服务
3. AI是AutoPM的核心差异化，不能依赖外部供应商
4. 数据安全和合规要求

### 具体分工

| 工作 | 谁做 | 为什么 |
|------|------|--------|
| 依赖地图的逻辑定义 | Sunny | 你理解业务，你知道谁卡了谁 |
| 异常雷达的规则定义 | Sunny | 什么时候标红标黄，你来定 |
| 信号推送的内容设计 | Sunny | 推什么、怎么推、推给谁 |
| 数据管道（ERP → AutoPM） | Agileex | 他们能走IT流程，你做不到 |
| Teams / 邮件推送技术实现 | Agileex | Power Automate + Teams Bot |
| 界面和报表 | Agileex | Power Apps界面 + Power BI报表 |
| AI接口预留 | Agileex | 架构上留好接口，SN AI团队未来接入 |

一句话：你定义大脑，Agileex搭建身体和管道。

### Rodyr/Ufuk的角色

最多做AI架构顾问，按小时付费，不深度绑定。取决于NDA能否解决。
