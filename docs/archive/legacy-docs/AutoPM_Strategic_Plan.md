# AutoPM 战略梳理：从今天到未来

> 2025年7月14日 · 整理全天讨论成果

---

## 一、你现在在哪里

AutoPM有一个能跑的网站（v14.8），有项目概览、甘特图、任务板、CSV导入功能，但**没有一行的真实项目数据、没有一个活人用户、没有数据访问权**。AI Insights是模拟的，60天路线图是基于假设画的。你1-2个人，隔2层级到Ross，困在改界面上出不来。核心死循环：没数据→没法证明价值→没资源→没法搞数据。

**诚实地说：你现在有一个demo，不是一个产品。**

---

## 二、你要去哪里

**AutoPM是SharkNinja的AI决策层——让7000人组织拥有70人小队的敏捷度。**

它不是比禅道好的工具，是禅道上面的那层大脑。它的交付物不是"请登录我的网站"，是"我帮你看到了一个你没看到的问题"。

---

## 三、你怎么去

### 阶段一：打破死循环（第1-2周）

**核心目标：拿到第一批真实数据，哪怕只有3个项目。**

要做的事：
1. **做CSV模板**：根据SharkNinja项目实际情况，设计一个5-10字段的CSV模板（项目名、阶段、负责人、DQTP状态、Compliance状态、延期天数），简单到PM花10分钟就能填完
2. **找3-5个PM手动填数据**：不要等API，不要等权限，拿着模板去找你认识的、关系好的PM，请他们喝杯咖啡，帮忙填3个项目数据
3. **搭Pipeline Analytics**：用规则引擎做统计分析（不叫AI），比如"3个项目中有2个卡在DQTP超过30天"——这是事实，不需要AI
4. **写一份诊断报告**：基于真实数据，3页PPT，说清楚"我看到了什么问题"

阶段交付物：3-5个项目的真实数据 + 1份数据诊断报告

成功标准：你能在一张纸上用真实数字说出一句话——"X个项目中，Y%卡在DQTP，平均延期Z天"，并且这个数字不是你编的

---

### 阶段二：诊断式交付（第3-4周）

**核心目标：拿着发现去找人聊，让人感兴趣，不是让人登录系统。**

要做的事：
1. **用阶段一的数据做深度诊断**：从统计升级到归因——为什么卡？卡在谁手上？卡了多少天？有没有规律？
2. **准备3种"电梯演讲"**：给Ross看的版本（组织效率+ROI）、给PM Leader看的版本（帮你提前发现问题）、给IT看的版本（不碰你们系统，我只需要数据）
3. **约3-5次15分钟聊天**：拿着诊断报告，不是演示网站，是讨论"你有没有这个问题"
4. **收集反馈并存档**：每次聊天后记录对方说了什么、关心什么、反对什么，用现有的反馈系统（JSON+git）

阶段交付物：诊断报告v2（带归因分析）+ 5次对话记录 + 至少1个表示"我想多了解一下"的人

成功标准：有1个决策者说"这个值得深入看"，且你拿到了接触更多项目数据的口头许可

---

### 阶段三：小规模验证（第5-8周）

**核心目标：在10-20个项目上验证AutoPM的判断力，积累可信案例。**

要做的事：
1. **扩大数据覆盖到10-20个项目**：通过阶段二的关系，拿到更多CSV数据或争取Jira只读权限
2. **验证Pipeline Analytics的预测力**：用规则引擎识别瓶颈，然后去和PM核实——"系统说你的项目可能卡在Compliance，对吗？"命中了就是证据
3. **开始标注行业基准**：用公开的行业数据（PMI报告、Standish CHAOS等）做对照，标注来源，说明"我们比行业基准差/好在哪"
4. **更新AutoPM网站**：把模拟数据全部替换为真实数据，Pipeline Analytics上线

阶段交付物：10-20个项目的真实数据看板 + 瓶颈预测命中率统计 + 行业基准对比

成功标准：命中率>60%（规则引擎判断的瓶颈，PM确认确实存在），且有2个以上PM主动说"这东西有用"

---

### 阶段四：争取资源（第9-12周）

**核心目标：拿着证据要资源，从1-2人扩展到3-5人，从手动数据到API接入。**

要做的事：
1. **写正式提案**：用阶段三的数据说话——多少项目、多少问题、节省多少时间/成本，引用《赋能》框架定位为组织进化项目
2. **向Ross或其直属汇报**：不是"我做了个工具"，是"我们发现了一个组织级问题，已经验证了解法，现在需要资源扩大"
3. **争取Jira API只读权限**：有了权限，数据从手动变自动，从20个项目到全量
4. **规划AI Insights真实版**：规则引擎验证完毕后，引入真正的ML模型（延期预测、风险评分）

阶段交付物：正式提案文档 + ROI估算 + 资源需求（具体到人头和时长）

成功标准：获得至少1个FTE的资源承诺或API访问权限

## 四、明天该做什么

### 1. 做CSV数据模板
打开Excel，设计一个最简模板：项目名、当前阶段、DQTP状态、Compliance状态、开始日期、预计完成日期、实际完成日期（如有）、延期天数。字段不超过8个，10分钟能填完。

### 2. 找一个PM填数据
打开通讯录，找一个你关系最好的PM，发消息："我在做一个项目分析，需要你帮我填3个项目的数据，大概10分钟，我请你喝咖啡。"别解释AutoPM，别发链接，只说需要数据。

### 3. 关掉编辑器，别改界面了
AutoPM的界面够用了。今天最大的坑就是"困在改界面上，其他事都做不了"。界面改到v14.8了，没人看就是零。明天一整天，改一行代码都算你输。去拿数据，去聊天，去推着事情往前走。

## 五、红线与原则

### 绝对不做
- **不拿模拟数据当真的说**——AI Insights的1500个项目模拟数据，对外一律不提，说了就是信用破产
- **不叫AI**——当前是规则引擎，就叫Pipeline Analytics，叫AI就是虚假宣传
- **不让人登录系统来"体验"**——没人会为了体验一个空系统注册登录，你的交付物是诊断报告，不是账号
- **不等API**——等Jira API就是等死，CSV手动填比API自动导出晚一天也比你等3个月强
- **不先做功能再做数据**——没有数据的功能是装饰品，1个功能+真实数据 > 20个功能+模拟数据

### 必须坚持
- **3行真实数据 > 1500行模拟数据**——任何场合，优先展示真实数据
- **诊断式交付**——先发现别人没看到的问题，再谈工具。拿着发现去找人，不是拿着工具去找人
- **每次对话都要有产出**——聊天不是目的，每次15分钟聊完要带回：数据、许可、或至少一条反馈
- **不粉饰现状**——对上级说"我有3个项目的数据"比说"我的系统能处理1500个项目"有用100倍
- **定位咬死"AI决策层"**——不做工具，不做禅道竞品，做禅道上面那层。这个定位变了，之前的路线全白费
