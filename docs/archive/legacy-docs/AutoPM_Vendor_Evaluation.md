# Ody vs Agileex 供应商评估

**日期：** 29 May 2026 | **评估人：** Sunny

---

## AutoPM需要什么

| # | 需求 | 含义 |
|---|------|------|
| 1 | 项目管理工具 | 能做出PM愿用的看板、里程碑追踪、任务管理、流程管理 |
| 2 | 数据自动汇聚 | 邮件、Teams、周报、月报、时间表、会议纪要自动拉取，不需PM手动填报 |
| 3 | AI洞察与风控 | 矛盾检测、风险预警、自动报告、AI问答 |
| 4 | 交付与扩展 | 50人Pilot→2000人全员，供应商能陪到底 |
| 5 | 数据主权 | 2000人的项目数据、商业机密在SN控制范围内 |
| 6 | 不被锁死 | 供应商做不下去时，换赛道的代价可控 |

## 二、两家 vs AutoPM需求

### Ody vs AutoPM

| AutoPM需求 | 匹配度 | 说明 |
|------------|--------|------|
| 1. 项目管理工具 | ★★☆☆☆ | 不懂PM，无PM案例。架构可定制，但谁来做PM设计？Ody不会，得SN自己来 |
| 2. 数据自动汇聚 | ★★★★☆ | 方向完全吻合——邮件/Teams/SharePoint/ERP都有连接器描述。但全部未在SN环境验证，且依赖IT开放API权限 |
| 3. AI洞察与风控 | ★★★★☆ | 6大Agent架构与需求高度匹配：矛盾检测、时间炸弹、Pattern Miner、Anomaly Radar。但准确率未知，误报高则PM不信 |
| 4. 交付与扩展 | ★★☆☆☆ | 小团队，Pilot可能跑得快，500人时服务能力存疑。无大规模案例 |
| 5. 数据主权 | ★★★★☆ | 自托管，数据不出SN网络，IT文档明确无phone-home |
| 6. 不被锁死 | ★★★☆☆ | 数据在SN的Postgres里，可迁移。但创业公司生存风险高 |

**总结：方向对了，但四项关键能力未验证（数据采集、AI准确率、交付规模、团队可靠性）。验证通过则高度匹配，验证失败则从头再来。**

---

### Agileex vs AutoPM

| AutoPM需求 | 匹配度 | 说明 |
|------------|--------|------|
| 1. 项目管理工具 | ★☆☆☆☆ | 自己确认"没做过PM系统"，"跟专业PM工具不是一个量级"。Power Apps做不出任务依赖、甘特图、里程碑管理 |
| 2. 数据自动汇聚 | ★★☆☆☆ | 确认手动填报。PM需要额外录入，信息墙未打破。Excel上传是批量填表的另一种形式 |
| 3. AI洞察与风控 | ★☆☆☆☆ | 无主动风控能力。可接千问做简单问答，但自己说"回答不准"。Power Apps Copilot国内用不了 |
| 4. 交付与扩展 | ★★★☆☆ | 130人团队交付没问题，4周MVP。但产品天花板在Power Apps——做到一定程度做不下去 |
| 5. 数据主权 | ★★★☆☆ | 微软云，SN已有环境，上线快。但数据不在SN控制范围 |
| 6. 不被锁死 | ★★☆☆☆ | 全部流程和数据深度耦合微软生态，迁移代价极大。做到天花板时换不掉 |

**总结：交付确定，但交付的不是AutoPM。MVP能出，但那是填报表+BI报表，不是项目管理平台。走到500人时撞天花板，推倒重来代价极大。**

---

## 结论

- **Agileex能力边界已确认——它不是AutoPM的供应商。** 快但方向错。
- **Ody方向对但未验证——必须先验证再决策。** 慢但方向可能对。
- **两家都不懂PM——SN必须自己承担流程设计。**

**下一步：与Ody深度验证会，用SN真实场景验证核心能力。通过则进Discovery，失败则找备选。**
