# AutoPM 60天行动计划：从"一个人干"到"拿到资源"

> 核心目标：**60天内让AutoPM被5+个真实项目团队持续使用，用数据拿到下一阶段正式资源（至少2个headcount + 工具预算）**

---

## Phase 1｜第1-2周：证明有人用

### 目标
3-5个真实用户在AutoPM上完成至少1个完整工作流，产出一组可展示的使用数据。

### 具体动作

#### 第1天（今天）
- [ ] 今天有同学来试用 → **全程陪同，录屏操作过程**，记录每一步卡点
- [ ] 用Google Sheet建一个「AutoPM用户追踪表」：列 = 姓名、项目、首次登录时间、完成动作、卡点、NPS评分(1-10)
- [ ] 准备一份5分钟的「AutoPM Quick Start」演示脚本（不要PPT，用Live Demo）

#### 第2-3天
- [ ] **先把你自己真实项目数据填进AutoPM**（OF102颜色项目、你管理的17个项目）
  - 目的：让AutoPM从"演示demo"变成"有真实数据的工具"
  - 手动填都行，不需要API，不需要公司系统权限
  - 截图你的真实项目在AutoPM上的样子，这就是最好的宣传素材
- [ ] 找3-5个一线PM，**不要说"配合试点"，说"帮你省时间"**
  - ❌ "CEO说你们部门配合AutoPM试点" → 对方觉得是额外负担
  - ✅ "你们Project-X最近逾期了，AutoPM能帮你提前看到风险，10分钟我给你看看" → 对方觉得你在帮他
  - ✅ "我自己的项目用AutoPM管着，逾期率降了不少，你要不要也试试？" → 分享经验，不是推销
  - 重点找：Tom/PD部门（产品开发PM最痛）、Evan/AI部门（技术团队最可能配合）
  - **先找你平时就有交集的人**，不要冷启动陌生人
- [ ] 给每个试用者建一个**专属Onboarding清单**：
  1. 登录网站
  2. 看我（Sunny）的真实项目怎么管的
  3. 试着创建1个项目
  4. 添加3个Task
  5. 查看1次Gantt Chart
- [ ] 每天下午5点，给每个试用者发一条消息：「今天用了没？卡在哪？」

#### 第4-7天
- [ ] 每个试用者完成Onboarding后，做一个15分钟**使用后访谈**，问3个问题：
  1. 你今天用AutoPM做了什么？
  2. 比你原来的方式，快了还是慢了？差多少分钟？
  3. 如果没有AutoPM你会怎样？(1-10分，多想继续用)
- [ ] 把访谈结果写进追踪表，标注「继续使用意愿」评分
- [ ] 根据卡点，**立刻修**Top 3体验问题（不要等，不要规划，改了就上线）

#### 第8-14天
- [ ] 目标：至少3个用户完成2周持续使用（每周登录≥3次）
- [ ] 开始记录**对比数据**：同一个项目，用AutoPM vs 不用AutoPM的耗时差异
  - 具体指标：Task创建时间、状态更新频率、项目进度可见性（原来多久看一次→现在多久）
- [ ] 每周五下午，给建发一条Update（见下方模板）
- [ ] 第14天，产出**Phase 1数据卡**（一页纸，见下方）

### 验收标准
| 指标 | 目标值 |
|------|--------|
| 完成Onboarding的用户数 | ≥ 3人 |
| 持续使用2周的用户数 | ≥ 3人 |
| 收集到的使用卡点 | ≥ 10条 |
| 修复的卡点 | ≥ 5条 |
| 用户继续使用意愿NPS | ≥ 7/10 |

### 关键原则
- **不追求完美**：网站有bug就陪用户绕过去，你手动帮他们填数据都行
- **人盯人**：3-5个用户，每天1条消息跟进，不能断
- **记录一切**：每一次使用、每一次卡顿、每一条反馈，都记下来，这是你后面谈判的弹药

## Phase 2｜第3-4周：证明有价值

### 目标
用Phase 1的使用数据，制作一份**老板和CDO看得懂的价值证明**，争取1次和Ross的面对面。

### 具体动作

#### 第15-17天：整理数据
- [ ] 从追踪表中提取以下核心数据：
  - **效率数据**：使用AutoPM前 vs 后，单个项目状态更新的平均耗时（例：原来邮件来回3轮→AutoPM 1次更新）
  - **覆盖数据**：多少个项目、多少个Task在AutoPM上管理
  - **粘性数据**：用户活跃天数/总天数、每日平均操作次数
  - **省钱数据**：粗算——如果PM每周节省X小时，按SharkNinja PM时薪，年化节省$Y
- [ ] 做一页纸的**AutoPM Value Snapshot**（不要PPT，就一张A4纸能打印出来的东西）：
  ```
  AutoPM 2周试点结果
  ━━━━━━━━━━━━━━━
  👤 活跃用户：X人（来自X个部门）
  📊 管理项目：X个 | 任务：X条
  ⏱ 平均效率提升：X%（基于X次操作对比）
  💰 预估年化节省：$X（X个PM × X小时/周 × $X/小时）
  🔄 用户留存率：X%（2周后仍在用）
  ⭐ 用户推荐分：X/10
  ```

#### 第18-21天：向上突破
- [ ] **跟建谈一次**（不是要资源，是「汇报进展+请求引荐」）：
  - 带Value Snapshot
  - 说：「建，AutoPM跑了两周，X个PM在用，数据在这儿。我想找机会跟Ross同步一下，你能不能帮我安排一次15分钟的会？」
  - 如果建说好 → 等他安排，同时自己准备
  - 如果建说不行/没时间 → **直接执行B线**（见向上管理策略）
- [ ] 同时，**给7位高管中的2-3位发「试点结果速报」邮件**：
  - 收件人：Tom(PD)、Evan(AI)、Corey(IT)
  - 标题：「AutoPM Pilot Update - Week 2 Results」
  - 内容：Value Snapshot + 1个用户原话 + 下一步希望他们部门扩大试用
  - 目的不是让他们立刻行动，是**让他们知道你在动**，保持温度

#### 第22-28天：扩大试点
- [ ] 利用Phase 1的3个用户做**内部推荐**：让他们各推荐1个同事试用
- [ ] 启动**颜色项目30天试点**（已有计划，立刻执行）：
  - 选1个正在进行的项目，用AutoPM全程管理
  - 每天更新项目状态到AutoPM
  - 试点结束时，对比「用AutoPM管理的项目」vs「没用AutoPM的同类项目」的进度可视化差距
- [ ] 如果用户数达到5+，做一次**用户群聊/会议**：
  - 让用户之间互相聊使用心得
  - 这是《赋能》的「共享意识」：让用户成为传播者，不是你一个人推

### 验收标准
| 指标 | 目标值 |
|------|--------|
| 活跃用户数 | ≥ 5人 |
| 完成Value Snapshot | ✅ 一页纸，数据齐全 |
| 和建的进展汇报 | ≥ 2次 |
| 和Ross接触（直接或间接） | ≥ 1次 |
| 颜色项目试点启动 | ✅ 1个项目在AutoPM上跑 |
| 效率提升数据 | 有量化数字（哪怕很粗） |

### 关键原则
- **用数据说话，不用愿景说话**：Ross和建不关心你未来要做什么，只关心你已经做了什么
- **省钱 > 省时间**：对管理层来说，"$X/year saved"比"省了X小时"有力100倍
- **一个用户原话 > 十个你自己的总结**：把用户说的话原封不动放进去

## 向上管理策略

### 跟建(Jian)的沟通

**现实**：建是你直属老板，但他隔2层到Ross，他给不了你资源，但他能**挡你**或**帮你开门**。

**策略**：
1. **永远让建知情**：每天的Update不是为了汇报工作，是让他觉得「这人很靠谱，不会出事」
2. **不向建要资源，向他要门**：不是「给我2个人」，而是「帮我安排一次和Ross的会，15分钟就够」
3. **让建成为共同作者**：在Value Snapshot和成果报告上，加建的name（哪怕他没参与）。他署名了，他就有动力推
4. **降低建的风险感**：建最怕你搞砸他背锅。每次Update都强调「小规模、可控、有数据」

### 绕过层级直达Ross/CEO

**不是越级，是按CEO指示执行**。CEO发了全公司邮件，你是在执行CEO的指令。

**Ross线**：
1. **首选**：通过建引荐（最安全）
2. **次选**：直接给Ross发邮件，标题带「Per CEO Mark's Directive」
3. **三选**：在Ross出席的会议上，Q&A环节举手提问：「Ross, I'm running the AutoPM pilot that Mark endorsed, can I get 15 min to share results?」
4. **注意**：每次接触Ross，都要让建知道。不是先斩后奏，是同步告知

**CEO线**：
1. **不轻易用**：CEO背书是你最大的牌，不能打两次
2. **用时要有结果**：去CEO那里必须带着60天数据，不是去诉苦
3. **通过EA/Chief of Staff**：不直接找CEO，找他的工作人员
4. **内容只写事实**：「60天，X个用户，X%效率提升，下一步需要X，当前卡在Y」

### 什么时机、用什么数据

| 时机 | 对象 | 带什么数据 | 目的 |
|------|------|-----------|------|
| 第2周末 | 建 | Phase 1数据卡 | 让建知道你在推进，请求引荐Ross |
| 第3周 | Tom/Evan | 用户反馈+使用截图 | 让高管知道有进展，保持温度 |
| 第4周末 | 建+Ross | Value Snapshot | 证明有价值，争取面对面 |
| 第6周末 | 建 | 60天成果报告草案 | 正式提出资源请求 |
| 第7周 | Ross | 成果报告+ROI | 拿资源承诺 |
| 第8周 | CEO EA | 1页总结（如需要） | 最后的杠杆 |

## 风险和应对

### 风险1：2个月后没拿到资源（最坏情况）

**应对**：
- 你已经不是零了——你有5+个用户、有使用数据、有用户endorsement
- 转为**影子运营模式**：AutoPM继续跑，你用1-2人的力量维护，不用正式编制
- 每月给建发一次数据更新，保持可见性
- 等下一个预算周期（通常是Q3/Q4 planning），带着积累的数据再次申请
- **关键心态**：没有资源不是失败，有用户在用就是成果

### 风险2：试用用户流失

**应对**：
- 流失是正常的，关键看**为什么流失**
- 如果是产品问题 → 修，哪怕丑陋地修
- 如果是老板不让用 → 这恰恰是你需要的证据：「PM想用但被阻止」
- 维持1-2个铁杆用户就够了，不需要10个

### 风险3：建不支持/消极

**应对**：
- 持续发Daily Update，哪怕他不回
- 在所有对外沟通中带上建的名字
- 如果建明确反对 → 问清楚具体原因，针对性解决
- 不对抗，不绕开，但**不停止推进**

### 风险4：Ross完全不理

**应对**：
- Ross不理 ≠ 项目失败。Ross的注意力有限，不代表他反对
- 通过Ross的下属（Director/Senior Manager级别）间接接触
- 让试用用户（来自Ross管辖部门）帮你在内部说好话
- 用户的声音 > 你自己的声音

### Plan B：如果60天后一切不顺利

**Plan B不是放弃，是转向**：

1. **从内部工具变成个人工具**：哪怕只有你自己和1个PM用，AutoPM也在产生价值
2. **开源外发**：如果SharkNinja内部推不动，考虑把AutoPM的核心逻辑开源，在外部建立影响力，反向影响内部决策
3. **找新盟友**：7位高管中，找到1个真正愿意配合的，把所有精力投在他那里，做深1个部门
4. **数据持续积累**：每天5个用户用一年 = 1200+人天的使用数据，这是任何下一轮谈判的最强弹药

### 障碍1：部门不回消息
**根因**：不是表达方式不对，是对方没看到"跟我有什么关系"
**对策**：

- 有了真实数据的AutoPM截图，就是最好的敲门砖

- 你的OF102试点就是你最好的案例——先用出来，再让人来问
