01

选择需要的权限

勾选项是申请范围，授权结果以 Airtable 为准。

企业权限 · 需要对应账户与管理员角色

      
Airtable 将新增、修改和删除记录合并为 data.records:write。选择 Base 的范围在官方授权页完成。

    

    
02
获取并设置 Token
Token 仅保存在当前浏览器会话中。

      

      

        
  1. 打开 Airtable 官方 Token 管理页，创建或编辑 Token。
  2. 按左侧清单选择 scopes，并添加你需要的 Base / 工作区。
  3. 保存后，将完整 Token 粘贴到下方验证。

        打开官方 Token 管理 ↗
        
        
        
PAT 的权限需在官方页面保存。修改左侧勾选不会直接修改现有 PAT；公开接口通常不返回 PAT 的完整 scopes。

      

      

        
首次配置 · 注册你自己的 OAuth 集成
          
  1. 打开 OAuth 集成管理 ↗，点击 Register new OAuth integration。
  2. 填写名称，将下面地址粘贴到 OAuth redirect URI。
  3. 启用左侧需要的 Permission scopes，保存。此浏览器插件使用公开客户端，不要生成 Client Secret。
  4. 将生成的 Client ID 粘贴到下方。供其他账户使用时，还需在集成中填写支持邮箱、隐私政策和服务条款网址。

          

        

        
        
        
登录并选择资源后，插件自动接收 Token。缩小现有 OAuth 权限可通过“应用所选权限”完成；新增权限会重新打开授权页。

      

      

        

        

        

        
实际授权的 scopes

        
清除只影响本机。如需撤销授权，请在 Airtable 官方账户 / Token 管理页操作。

      

    

  

  
03
验证 Base，导出连接
使用只读请求验证身份、表结构与记录读取，不更改业务数据。

    

    
Base 列表与表结构读取需要 schema.bases:read。也可手动填写 Base 和表 ID。

    

    

    
导出的 JSON 包含完整 Token。导入 AutoPM：连接设置 → 导入已有 sync_config.json → 保存连接设置。

    
OAuth Token 会过期，AutoPM 当前不会自动刷新。长期连接建议使用 PAT；OAuth 导出仅适用于显示的有效期。

  

  
权限由 Airtable 执行 · 密钥不写入浏览器同步存储 · 不读取网页 Cookie 或登录凭据 使用说明
