# 字段映射与分表规则

本文件记录当前代码的默认语义映射。实际运行会优先使用按 Base 保存的字段 ID，并在每次预览时重新核对字段名称、类型、关联表和选项。字段 ID 比名称稳定；字段删除重建、类型变化或关联目标变化必须重新审核。

## 1. Projects 表

| 语义键 | 默认 Airtable 字段 | 用途 |
|---|---|---|
| `project_id` | Project ID (Manual) | 历史/显示编号及基本身份 |
| `project_number` | Project Number (Manual) | 正式项目编号 |
| `project_name` | Project name (Manual) | 项目名称 |
| `sku` | Project SKU (Manual) | Airtable SKU 管理身份 |
| `factory` | Factory (Manual) | 工厂关联 |
| `status` | Project Status (Manual) | 项目状态 |
| `brand` | Brand (Manual) | Shark/Ninja 等品牌 |
| `type` | Project Type (Manual) | 项目类型 |
| `quality` | Quality Owner (Manual) | Quality 人员关联 |
| `npi_lead` | NPI Owner (Manual) | NPI 人员关联 |
| `npd_lead` | NPD Owner(Manual) | NPD 人员关联 |
| `pmo` | PMO Owner (Manual) | PMO 人员关联 |
| `current_progress` | Engineering remark(Manual) | 周报工程进展和版本块 |
| `update_this_week` | Current stage | 当前阶段/本周更新 |
| `jira_summary` | Jira summary (Manual) | Jira 摘要 |
| `jira_link` | Jira URL (Manual) | Jira 链接 |
| `tooling` | Tooling (Manual) | Tooling 文本 |
| `kick_off_date` | Kick Off Date (Manual) | 项目直接日期，同时可能有 Task |
| `dqtp_finish_date` | DQTP Finish Date (Manual) | 项目直接日期，同时可能有 Task |
| `mp_aw_date` | MP AW Date (Manual) | 项目直接日期，同时可能有 Task |
| `compliance_complete_date` | Compliance Complete Date (Manual) | 项目直接日期，同时可能有 Task |
| `start_date` | Start Date (Manual) | Award/开始日期 |
| `mp_start_date` | MP Start Date (Manual) | MP Start 日期 |
| `report_date` | Weekly Report Update Date (System) | 旧版版本字段；Engineering Remark 模式下禁用 |
| `next_plm` | Next Action | 下一行动 |
| `loa_13weeks_plan` | LOA-13weeks plan(Manual) | 13 周计划 |

当前主库使用 Engineering Remark 保存周报版本，因此 `report_date` 不作为必需写入字段。Project 身份和当前版本字段是全局阻断项；多数非关键字段缺失或类型不兼容时只跳过该字段并记录提示。

| 语义键 | 默认 Airtable 字段 | 规则 |
|---|---|---|
| `name` | Task Name (Manual) | 任务名称/身份 |
| `project` | Projects (system manage) | 必须关联 Projects 表 |
| `start_date` | Start Date (Manual) | 有明确来源才写 |
| `due_date` | Due Date (Manual) | 周报时间轴日期主要写入处 |
| `milestone` | Milestone (Manual) | 仅写现有且唯一匹配的选项 |
| `owners` | Tasks Owners (Manual) | 解析为 People record ID |
| `completed_by` | Completed By (Manual) | 明确完成信息才写 |
| `latest_update` | Latest update (Manual) | 任务更新文本 |
| `duration` | Duration for Start Date (Auto) | 配置允许且字段可写时维护区间 |

## 5. All Tracker 大里程碑列

当前可识别：First CRD、Kick Off、TRA/ECN DD、Cut Steel、FOT、EB1、EB2、EB3、Pilot、Tooling Transfer Load、Tooling Transfer Arrival、MPRA/ECN、MP Start、Previous MP、P1/P2/P3 CAD DROP、P1/P2/P3 BUILD DATE、Last P、Last P BUILD DATE、13 Weeks Release、AS Release、Color Approval、DQTP、Compliance、FPO、MP AW Release。

导出时这些值主要来自 Tasks 的里程碑和 Due Date。若同一项目同一里程碑存在多个候选，程序不会压成一个日期，而会保留提示并跳过该单元格。

## 6. 哪些信息不进入 All Tracker

- 完整 Issue/Recovery Action 明细。
- 普通非里程碑 Task 的全部详情。
- 多个地区节点无法安全聚合时的日期。
- 无明确总表列的字段。
- 公式列的替换值。
- 空值导致的清空操作。

这些内容仍保留在 Airtable 和预览/提示中，All Tracker 只承担 Dashboard 角色。

## 7. 字段变更处理

- 字段改名但 ID 未变：映射记忆可继续使用。
- 字段删除后用同名字段重建：ID 变化，必须重新审核。
- 字段类型或 Link 目标变化：停止相关路径。
- Select 新增/删除选项：重新生成预览；不自动创建选项。
- 映射不到的非关键字段：提示并跳过，不应阻断整个批次。
- Project 身份、版本字段、表身份不完整：阻断批次，防止错写。
