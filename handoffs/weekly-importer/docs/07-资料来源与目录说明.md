# 资料来源与目录说明

## 1. 当前源码快照

`source/` 来自 2026-09-21 本地工作目录 `AutoPM_Source_20260915` 的技术文件快照。为保证交接可用，复制后只调整了两处支持文件：`README.md` 改为仓库相对链接；`_verify_runtime.py` 改为直接调用生产日期解析函数，避免它自己的旧复制逻辑误报 ordinal 日期失败。业务模块未改动。

已包含：

- `autopm/` 全部 Python 业务模块。
- `tests/` 全部自动测试。
- `benchmarks/` 评测辅助代码。
- `browser-extension/airtable-token-helper/` 浏览器授权助手及测试。
- `assets/` 品牌资源、字体和许可证。
- `packaging/` 历史 PyInstaller spec。
- 启动、构建、自检和验证脚本。
- 非敏感配置示例和源文件清单。

未包含：

- `.venv`、`__pycache__`、build、dist。
- `.local` 设置、映射记忆、模型缓存和 DPAPI 密文。
- `Run Logs`、Airtable schema/record 快照和写入日志。
- `Airtable token API.txt` 或任何真实 Token/API Key。
- 原始周报、真实 All Tracker 和包含项目数据的审核 CSV/XLSX/HTML。
- `updates.json`、`sync_progress.json`、`excel_maps.json` 等历史真实数据同步产物。

## 2. reference 文档

`docs/reference/` 保留历次技术分析和验证。阅读时遵循：

- 本交接目录的 01-07 文档代表最新整理结论。
- reference 是来源证据，不自动代表当前规则。
- 文件中若出现旧字段、旧版本或旧业务假设，以当前代码、当前 schema 和用户最新确认原则为准。
- `DUMATE_ALL_TRACKER_handover.md` 描述过一次历史数据操作，其中引用的真实数据文件没有随包上传。

## 3. legacy-reference

早期独立工具主要用于从 All Tracker 的 Project Name 和 Engineering Remarks 向 Airtable Projects 写入增量备注。它与当前桌面工具存在重要差异：

- 早期工具以项目名称为主要匹配键。
- 当前工具有 schema memory、正式编号/SKU/工厂身份、Task/Issue、写前守卫、写后回读和双向总表流程。
- 早期工具只应作为历史算法和界面参考，不能替代当前 `source/`。

`weekly_importer.json` 未包含，因为它可能含真实凭据；只保留 `.example`。

## 4. 维护规则

- 新开发以 `source/` 为基线。
- 修复后同步更新本交接文档和测试证据。
- 任何新增 fixture 必须脱敏，不使用真实人员、项目进展或 Token。
- GitHub Issue/PR 记录当前执行状态；本目录说明系统行为和交接背景。
- 生产写入、删除、合并和 schema 改动需要单独授权与预览。
