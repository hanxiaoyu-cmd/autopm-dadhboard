# 数据流与匹配规则

## 1. 三条数据流

### A. 周报 -> Airtable

```text
Excel 周报
  -> workbook.read_workbook：读取单元格、颜色、合并区域和来源坐标
  -> workbook.parse_local 或 DeepSeekClient.parse：形成标准 report
  -> schema_memory.reconcile：核对 Base、表、字段 ID、类型、关联目标和选项
  -> sync.build_plan：生成只读预览、警告、阻断和写入守卫
  -> sync.apply_plan：写前重读、执行写入、写后回读校验
```

### B. Airtable -> All Tracker

```text
Airtable 新鲜 schema + 全量相关记录
  -> airtable_tracker.snapshot_to_report：转换为统一 report 结构
  -> tracker_roundtrip.export_plan：按编号、SKU、工厂绑定 Excel 行
  -> tracker.build_tracker_plan：生成单元格级变化
  -> tracker.export_tracker：另存 Excel 副本和 .autopm.json 回写基线
```

### C. All Tracker -> Airtable

```text
此前导出的 Excel 副本 + .autopm.json
  -> tracker_roundtrip.writeback_plan：比较导出基线、本地当前值、云端当前值
  -> 只生成有明确绑定且无冲突的字段变化
  -> sync.apply_plan：使用同一套写前守卫和写后校验
```

## 2. 当前项目身份匹配算法

代码位置：`source/autopm/identity.py`、`source/autopm/sync.py`。

### 2.1 正式编号

目标记录的正式编号按以下顺序确定：

1. `Project Number (Manual)` 非空且不以 `X` 开头时使用它。
2. 否则使用非 `X` 的 `Project ID (Manual)`。
3. 两者都是 `X` 或空值时，视为未绑定的临时记录。

来源周报必须提供非 `X` 的正式项目编号。项目名称不能替代编号。

### 2.2 SKU 和工厂

- SKU 按逗号、分号、中文逗号、中文分号和换行拆分，去空格并转大写。
- 工厂文本必须通过 Factories 表解析为唯一一个 Airtable record ID。
- 每个候选目标必须同时满足 SKU 与工厂完全匹配。
- 一个 Airtable 管理记录只能含一个 SKU；含多个 SKU 的记录会被跳过并提示先拆分。
- 同一 `SKU + 工厂` 下如同时存在正式记录和未绑定 `X` 记录，候选不唯一，停止自动匹配。
- 未绑定 `X` 记录只有在 `SKU + 工厂` 唯一时才可绑定；写入时把来源正式编号写入 `Project Number (Manual)`。

### 2.3 禁止的回退方式

当前严格模式明确不使用：

- 项目名称模糊匹配。
- 仅凭 SKU 匹配。
- 仅凭项目编号忽略工厂匹配。
- 自动选择多个候选中的第一条。
- 自动创建人员、工厂或下拉选项。

### 2.4 写入前身份守卫

预览会保存目标 record ID、项目编号、SKU、工厂以及相关字段原值。正式写入前重新读取云端；只要身份不再唯一、record ID 改变或守卫字段变化，就要求重新生成预览。

## 3. Project、Task、Issue 的分流

### 3.1 Project

项目主信息、负责人、状态、工程备注、当前阶段、Jira 摘要和部分直接日期写入 Projects 表。`Current Progress` 通过 `weekly_remark.py` 合并到 `Engineering remark(Manual)`，保留手工备注和历史。

### 3.2 Task

周报时间轴中具有明确日期的节点进入 Tasks 表。任务身份首先按“项目 + 标准化任务名称”匹配；没有名称命中时，可在同一项目内按唯一里程碑匹配现有模板任务。

里程碑处理规则：

- 先把地区后缀与任务文字标准化，再应用配置别名和内置别名。
- 只有 Airtable `Milestone (Manual)` 已存在对应选项时才写入该选项。
- `require_milestone=false` 时，没有里程碑选项的任务可以作为普通 Task 导入；为 `true` 时直接跳过。
- 同一项目同一里程碑有多个来源且日期不同，会跳过并提示人工核对。
- CN、VN 等地区范围不同的任务不会互相覆盖。
- 绿色完成状态仅在存在明确可写完成字段时写入；否则只保留在预览提示中。

常见别名包括：

| 周报名称 | 标准里程碑 |
|---|---|
| Kick off / Kick off date | Kick off |
| Award / Award date | Award |
| DQTP / DQTP Finish | DQTP report |
| Compliance Complete | Compliance report |
| MP AW | MP AW release |
| New MP Start / MP Start Date | MP Start |
| Previous / Old MP Start | Previous MP Date |
| TRA / ECN DD | TRA / ECN DD |
| MPRA / ECN IMP | MPRA / ECN |
| P1 / P2 / P3 | 对应 BUILD DATE |
| EB1/2/3 Date | EB1/2/3 |
| Cut Steel Date | Cut Steel |
| Pilot Date | Pilot |
| Tooling Transfer Load/Arrival Date | 对应 Tooling Transfer 节点 |
| 13 Weeks / AS / Color / FPO | 对应标准选项 |

### 3.3 Issue

问题明细进入 Issues 表，包含问题描述、Recovery Action、记录日期、风险等级、负责人和计划关闭日期。

- 本地规则解析默认按精确问题文本匹配。
- DeepSeek 抽取模式可以启用修订匹配，但模型输出不能决定表 ID、字段 ID、目标 record ID 或任意写入。
- 问题候选不唯一时不新增、不覆盖，保留提示供人工核对。

## 4. 人员、工厂、选项和日期

### 人员

- 通过 People 表解析为 record ID。
- 可使用显式 alias。
- NPI、NPD、PMO、Quality 等字段可按部门约束候选。
- 0 个或多个候选都不写入，不自动创建人员。

### 工厂

- 通过 Factories 表和配置别名解析。
- 必须唯一。
- 解析不到或多个候选时，该管理单元不匹配。

### Single Select / Multiple Select

- 只接受当前 schema 中已有选项。
- 大小写和空格标准化后必须唯一对应。
- 程序不自动新建选项。

### 日期

- 目标格式为 `YYYY-MM-DD`。
- 无年份日期依赖报告日期推断，并受跨年窗口保护。
- 含删除线、年份歧义、无明确日期的节点跳过。
- 旧周报日期早于 Airtable 已存版本时，整个项目跳过。

## 5. Engineering Remark 合并与重复导入

新格式：

```text
--- 2026-09-17 ---
本周进展正文
```

规则：

- 保留原手工备注和历史块。
- 同日期、同内容重复导入不追加。
- 新日期但内容不变时只追加空日期块，用于推进版本，不重复正文。
- 旧日期不能追加到更新版本之后。
- 正文不得伪造日期分隔行或保留的旧 AutoPM 标记。
- Airtable 可能重排 Markdown 有序列表编号并增加结尾换行；比较时只规范列表编号格式，正文、日期、数量、转义数字和代码块仍严格比较。

## 6. All Tracker 导出匹配

All Tracker 行必须含项目编号、SKU、Manufacturing Factory/Factory。每行通过当前严格身份规则绑定一个 Airtable `Projects` 记录。

- 同一记录不能对应多个正式编号。
- 公式单元格不作为覆盖目标。
- 项目字段可写入项目列；Task 只输出已识别的里程碑日期。
- Issue 明细不展开到总表；以提示说明未输出。
- 导出必须另存副本，不能覆盖输入文件。
- 同时生成同名 `.autopm.json`，保存回写所需的 record ID、字段 ID、schema、导出前云端值和 Excel 基线。

## 7. All Tracker 回写保护

回写只处理导出时建立过绑定的单元格：

1. Excel 和 `.autopm.json` 必须同时存在且属于同一 Base。
2. 项目编号、SKU、工厂仍须唯一对应原 record ID。
3. 表、字段 ID、字段类型和选项必须与导出时一致。
4. 公式不写回；空白不用于清空云端字段；删除列也不代表删除云端数据。
5. 本地值等于导出基线时不处理。
6. 云端值等于导出基线而本地已改时，才形成回写候选。
7. 云端和本地都已改时停止，提示冲突，不覆盖云端。
8. Task 的项目、名称或里程碑变化时停止绑定。

## 8. 业务目标与当前算法的关键差距

当前严格算法在一个 `Projects` 表记录上同时使用项目编号、SKU 和工厂。业务原则则要求 Project 内容独立于 SKU。

接手者需要决定并实现以下模型之一：

- 建立明确的 Project 父记录，SKU/工厂作为子记录；Task 和 Issue 只关联父 Project。
- 保留当前 SKU 记录，但增加稳定的 Project Group ID，并让项目级内容只写一份、Task/Issue 关联 Project Group。
- 如果现有 Airtable schema 已有可承担父级的对象，复用该对象并迁移当前绑定。

在该决定完成前，不应通过“对所有 SKU 都写一遍”来伪装项目级支持。
