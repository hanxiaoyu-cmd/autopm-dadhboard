## 一、根因（为什么 "一直发生"）

报错文本 `操作未完成：'current_progress'` 的唯一来源是 Python `KeyError('current_progress')` 经 `str()` 转换后的标准形态（`str(KeyError('current_progress')) == "'current_progress'"`）。

真正的炸点不在此前排查的 `build_plan` 内部，而在它**之前**的必走前置阶段：

```
sync.py  L97  required_project_types(config)
         L100 return {key: REQUIRED_PROJECT_TYPES[key] for key in ("project_id", version)}
```

- 用户配置 `project_report_storage = engineering_remark` → `uses_weekly_remark(config)` 为 True → `version = "current_progress"`；
- 而 `REQUIRED_PROJECT_TYPES` 字典（sync.py L87-94）**从未包含 `"current_progress"` 键**（也没有 `"report_date"` 键）→ `REQUIRED_PROJECT_TYPES["current_progress"]` 必然抛 `KeyError('current_progress')`；
- 该函数在两条前置路径被调用，都会先于任何可读提示崩溃：

1. `schema_memory.py` L224 `key in required_project_types(config)`（reconcile 阶段，`prepare_preview` 第一件事）；
2. `schema_memory.py` L306 同上（必需字段 blocker 检查）；
3. `sync.py` L533 `for key, expected in required_project_types(config).items()`（build_plan 阶段）。

**此前两次修复为什么没解决**：第一处修的是 `build_plan` L540 用 `.get()` 取 `version_field`（那是另一个 TypeError 炸点）；第二处修的是 `weekly_remark.py` 重复 `return text`。二者都在 `required_project_types()` 抛 KeyError **之后**才执行，所以错误始终复现——这就是"一直发生"的真相。

## 二、修复内容

### 修复 1（本次主故障）— `autopm/sync.py`

`REQUIRED_PROJECT_TYPES` 补齐活动周报版本字段的两个键：

```python
REQUIRED_PROJECT_TYPES = {
    "project_id": "singleLineText",
    "current_progress": "richText",   # 新增：weekly-remark 模式的版本字段
    "report_date": "date",            # 新增：legacy 模式的版本字段
    "kick_off_date": "date",
    ...（原有键不变）
}
```

- `current_progress` 云端实际类型为 `richText`（已验证 .local/live_schema.json：Projects → Engineering remark(Manual) → richText），与 `project_type_matches()` 的放行规则一致，不会引发新的 blocker。
- `report_date` 同步补齐：未启用 remark 存储的配置同样会命中 `REQUIRED_PROJECT_TYPES["report_date"]`，此前同样必炸。

### 修复 2（模拟中发现的新故障）— `autopm/schema_memory.py`

`compatibility()` L136 用 `key.endswith("date")` 判定日期字段，导致 `latest_update`（末尾 "up**date**"）被误判为日期字段；而云端 `Latest update (Manual)` 是 `multilineText` → 误报 "须为 date；跳过此字段" → 本地总表（`prepare_airtable_tracker`）整条链路被 `SchemaMemoryError` 阻断。

修复为与全项目权威定义（`workbook.py` L88 `endswith("_date")`）一致：

```python
if key.endswith("_date") and field["type"] != "date":
    return "须为 date"
```
