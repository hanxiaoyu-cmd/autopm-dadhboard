# 周报导入修复与验证（2026-09-15）

## 故障原因

1. 当前本地设置只有连接信息，没有加载已有的主库字段映射和备注合并配置，因此程序仍查找默认的 Current Progress、Update This Week、Weekly Report Update Date。实时 Airtable 中不存在这些默认字段；实际使用 Engineering remark(Manual)。
2. 原程序把多个内容字段设为全局必需项，结构核对发现缺失就返回空计划；一项问题会阻断整份周报。

## 本次修复

- 依据实时表结构核验已有映射示例，再补入当前 Base 的本地设置；Token 使用原有 Windows 加密存储。
- 内容字段未匹配、只读、类型变化或删除时，仅跳过此字段并保留提示、原周报及解析日志。
- 单个项目不安全时跳过该项目；任务/问题结构不满足要求时跳过对应内容，其他有效内容继续处理。
- 按 Base 保存字段 ID；字段改名可以自动适应。失效映射保留原 ID，避免删除重建后错误地匹配同名字段。
- 身份、周报版本、防止并发覆盖及错误关联的检查仍保留；不会为不确定内容虚构人员、日期或选项。
- 复用已有“映射记忆”界面，可手动调整或使用 DS 提供候选建议。业务代码没有新增当前主库专用 ID。

## 验证结果

- 393 项自动测试通过，含失效字段的隔离、有效内容实际写入模拟、重复导入零变更、跨 Base 隔离和并发保护。
- 通过启动源码版.cmd 启动，检测到“AutoPM · 项目同步工作台”窗口且响应正常。
- 实际联网核对和同步调用工作台共用的 prepare_preview / apply_plan；未声称完成桌面逐按钮操作验收。

## 后续使用

1. 双击启动源码版.cmd，选择周报，运行规则检查并生成 Airtable 预览。
2. “提示与检查”中可查看待映射/已跳过内容；进入“映射记忆”修改目标字段后重新预览。
3. 正常差异可直接确认同步；重复导入同样内容不会重复追加备注。
4. 若整个项目身份或周报版本存储失效，须先修复该关键映射，防止写错项目或旧数据覆盖新数据。
