# 架构、运行与安全

## 1. 主要模块

| 模块 | 职责 |
|---|---|
| `app.py`, `autopm/ui.py`, `tracker_ui.py` | Windows 桌面界面和异步任务调度 |
| `workbook.py` | 读取周报单元格、样式、颜色、日期和来源坐标 |
| `deepseek.py` | 可选 AI 抽取；输出必须通过确定性校验 |
| `schema_memory.py` | 按 Base 保存稳定表/字段 ID，并重新核对结构 |
| `identity.py` | 正式编号 + SKU + 工厂身份匹配及写入守卫 |
| `sync.py` | 生成 Airtable 写入计划、执行写入、写前/写后校验 |
| `weekly_remark.py` | Engineering Remark 历史读取、增量合并和富文本等价比较 |
| `airtable.py`, `network.py` | Airtable HTTP、TLS、重试、速率限制和安全日志 |
| `airtable_tracker.py` | 把 Airtable 快照转换为统一 report |
| `tracker.py` | 读取 All Tracker、表头映射、单元格差异和原生副本导出 |
| `tracker_roundtrip.py` | Airtable 导出绑定及 All Tracker 三方回写 |
| `native_xlsx.py` | 保留原生 XLSX ZIP 部件，避免无关格式损坏 |
| `preview.py`, `presentation.py` | HTML/界面预览和提示分类 |
| `config.py` | 本机设置、环境变量和 Windows DPAPI 密钥保护 |

## 2. 核心中间数据

### Report

解析周报后的标准结构：

```text
report
  report_date
  source
  projects[]
    project_id
    report_date
    fields{}
    tasks[]
    issues[]
    source/evidence
```

### Snapshot

从 Airtable 新鲜读取：

```text
snapshot
  base_id
  table_ids
  schema
  records{table_id: [...]}
  captured_at
```

### Plan

可审核、可验证的变化计划：

```text
plan
  changes[]
  warnings[]
  blockers[]
  project_guards[]
  schema/table_ids/base_id
  plan_id
```

Plan 不是写入成功证明。只有 `apply_plan` 完成写前重读、API 返回和写后回读等价检查，才算验证通过。

## 3. 配置与凭据

- 源码模式设置：`source/.local/settings.json`，本包未包含。
- 打包模式设置：`%LOCALAPPDATA%\AutoPM-Preview\.local\settings.json`。
- Token 和 DeepSeek Key 使用 Windows DPAPI 加密；也可使用 `AIRTABLE_TOKEN`、`AIRTABLE_BASE_ID`、`DEEPSEEK_API_KEY` 环境变量。
- `config.main-base.example.json` 只含已确认的非敏感主库映射示例。
- 任何真实设置文件、Token 文本和加密凭据都不能提交 Git。

## 4. 网络与 TLS

当前网络层：

- 使用系统信任库验证 Airtable 与 DeepSeek TLS。
- 尊重显式 `SSL_CERT_FILE` / `SSL_CERT_DIR` 和系统代理。
- 不关闭证书校验或主机名校验。
- 对可安全重试的网络错误做有限退避。
- 写入超时或结果不确定时不盲目重试，要求核对远端状态。
- 网络报告不记录 Token、请求正文或业务记录内容。

## 5. 写入保护

- 预览和写入绑定同一 Base、schema hash、表 ID 和字段 ID。
- 写入前重新读取项目身份和报告版本。
- 创建 Task/Issue 前检查是否出现等价记录。
- 更新前确认目标 record ID 和 before 值仍匹配预览。
- 写后回读实际字段；不等价时记录 record ID、字段预期值/实际值和 `written_unverified`。
- 日志保留不确定结果，防止下一次运行把已成功写入误当成未执行。

## 6. 源码运行与测试

```powershell
Set-Location source
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

运行全部测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
```

源码自检：

```powershell
.\.venv\Scripts\python.exe app.py --self-test --report "<周报.xlsx>"
```

测试真实 Airtable 前应使用只读预览。不要把“连接成功”“schema 可读”或“预览生成”称为正式写入成功。

## 7. 打包

`source/build.ps1` 和 `source/packaging/` 保留历史 PyInstaller 配置。当前交接以源码为准，未携带 EXE。若需重新封装：

1. 先修复已知问题并跑全量测试。
2. 在空白本机配置和无 Python PATH 环境验证启动。
3. 检查 EXE 不含 Token、`.local`、日志、业务 Excel 或 Airtable 快照。
4. 公司设备可能拦截未签名 EXE，不能把个人电脑启动成功当成公司环境验收。
