# 更新日志

## 2.4.0-rc5 — 2026-09-21

问题：Airtable 已读取成功后，本地 All Tracker 中的 Excel 纯时间值导致 `Object of type time is not JSON serializable`，无法生成预览和导出副本。

根因：`tracker.scalar()` 仅转换 `datetime` 与 `date`；openpyxl 还会返回 `time` 和 `timedelta`。全部非空格（包括空项目行）参与 JSON 内容指纹，导出后的旁路审计和回写基线也依赖相同值。

变化：

- 时间转换为 ISO 文本，时长转换为保留跨天及微秒的文本；完整日期的既有规范和指纹结构不变。
- 日期列中的时间／时长给出工作表、坐标和表头提示，传递到导出与回写预览；不推测缺失日期。
- 未改动单元格继续保留原生 XML。云端完整日期实际更新纯时间格式格时，为目标格设置日期显示格式。
- 版本真源升至 rc5，更新启动说明和交接状态；本次不构建 EXE。

验证：

- [7 项新增合成回归](source/tests/test_tracker_temporal_values.py)：修复前复现 JSON 错误及时间格式问题，修复后全部通过。
- 完整 `python -m unittest discover -s tests -v`：435 项通过，38.819 秒；运行时自检及桌面启动自检通过。
- 本轮 Airtable 只读采集为 169 次 GET，0 次写入。使用该快照在当前源码中本地回放导出：用户指定总表 399 个项目行，按现有严格身份及周报版本规则选入 135 行，更新 406 格。其余行保留原值，未扩大匹配规则。
- 实际写出新的本地 Excel 副本及 `.autopm.json`；原表 SHA-256 未变，19,505 个公式及 75 个非目标 ZIP 部件保留。215 个更新日期格均使用日历日期格式。
- 同一快照再次导出计划为 0 变更；未编辑副本回写预览为 0 变更、0 阻断。未执行真实 Airtable 回写。

边界：历史诊断中的 V2 原文件本轮未提供，使用合成异常值复现；用户本轮指定总表本身未出现纯时间值。现有项目身份、缺少映射和版本提示仍按原规则处理。4 个不支持本地重算的公式缓存需在 Excel 中刷新；完整业务模型改造不在本次范围。业务文件、快照、配置、凭据和详细日志仅保留在本机。
